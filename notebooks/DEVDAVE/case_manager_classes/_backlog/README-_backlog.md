# README for the _backlog folder of totodev_pub library

When proposing a refactor or other change to the library, write up the suggestion for review and discussion with maintainers. This process is not necessary for routine bug fixes unless the change would be breaking.

A proposal stays in this folder for its whole life. Its **status is not tracked here** — it is tracked in the closeout tracker that owns the work, currently `notebooks/DEVDAVE/case-queue/TRACKER.md`, which records what shipped, what was deferred, and what was rejected along with the reasoning. When a proposal's status changes, put a one-line pointer at the top of it and let the tracker carry the detail.
